<objective>
Make `ToolRegistry` safe to mutate from a second thread, and give it an identity-checked removal —
the precondition for plan 12-04 wiring MCP death/reconnect into `Harness.registry` (orchestrator
decision: the MCPManager <-> ToolRegistry desync is in scope, research Open Question 1 / Pitfall 4).

Purpose: `MCPManager.on_tools_changed` (plan 12-01) fires on the MCP loop thread, while `run_turn`
reads `registry.specs()` and dispatches on the harness thread (and parallel read-only tool calls
dispatch from a ThreadPoolExecutor). A plain dict mutated across threads is the exact hazard
research Pitfall 4 names; `Harness` already uses `threading.Lock` for the same class of problem
(`_subagent_usage_lock`), so a lock is the project's own precedent. Chosen mechanism: an
`RLock` inside ToolRegistry (not marshalling to the main thread), because the registry must stop
offering a dead server's tools immediately, not at the next turn boundary, and every reader already
goes through ToolRegistry methods (`grep "registry._tools" src/` finds no outside access).

Output: locked registry + `unregister_tool`, with tests. Independent of plan 12-01 (no shared file).
</objective>

2. In `__init__`: `self._lock = threading.RLock()` with a comment: MCP death/reconnect (MCP-26/MCP-23) mutates the registry from the MCP manager's background event-loop thread while the harness thread reads it; RLock so `dispatch` can call `names()` for its error text while holding it.

```python
with self._lock:
    tools = list(self._tools.values())
return [t.spec() for t in tools]
```
5. `dispatch()`: only the lookup is under the lock; `_skill_refusal` and `tool.run(call, ctx)` run OUTSIDE it (a tool run can take minutes and a delegate tool re-enters the registry):
```python
with self._lock:
    tool = self._tools.get(call.name)
if tool is None:
    return ToolResult(..., error=f"Unknown tool '{call.name}'. Available: {', '.join(self.names())}.")
```
6. New method, right after `unregister`:
```python
def unregister_tool(self, tool: Tool) -> bool:
    """Remove ``tool`` only if it is the object registered under its name.

    An MCP server that dies mid-session reports the Tool objects it had mounted (MCP-26). If
    one of those names lost a startup collision, the registered owner is a DIFFERENT tool (a
    built-in, or another server's) — removing by name alone would delete the wrong one.
    """
    with self._lock:
        if self._tools.get(tool.name) is tool:
            del self._tools[tool.name]
            return True
        return False
```
Do not change `default_registry` or any signature. `unregister(name)` keeps its existing behaviour (used by `Harness.remove_mcp_server`).
