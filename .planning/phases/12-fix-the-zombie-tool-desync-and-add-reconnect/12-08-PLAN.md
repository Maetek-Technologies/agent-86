<objective>
Gap closure from 12-07 Task 3 human verification. The reconnect machinery works (killed PID came back
in 1.75 s, tools re-registered) but the user sees nothing: `MCPManager` appends drop/reconnect notes
to `manager.notes`, and the TUI only renders those once at mount. Folded in by user decision: the
start-failure note is opaque (`failed to start: unhandled errors in a TaskGroup (1 sub-exception)`)
and the stdio child's stderr — which holds the real reason — goes to the terminal, invisible under
the TUI.

**Mechanism chosen (and why): a push hook.** `MCPManager` gets a listener list called on every
`_add_note` (on whichever thread added the note — usually the MCP loop thread), outside its lock,
never raising. `Harness` subscribes one forwarder per manager (in `_wire_mcp`, so managers created
later by `ensure_mcp()` are covered) and forwards to `Harness.on_mcp_note`, which the TUI sets on
mount. The TUI marshals with **`App.post_message`**, NOT `App.call_from_thread`: Textual 8.2.8's
`post_message` is thread-safe (`loop.call_soon_threadsafe(...put_nowait)` off-thread, direct put
on-thread) and non-blocking, whereas `call_from_thread` blocks the caller until the UI runs the
callback and raises if called on the app thread — a deadlock with `stop_server()` (called on the UI
thread, blocking on `.result()` for the MCP loop) whenever the loop thread emits a note during that
stop. A push hook (vs. drain-per-turn) is what makes a disconnect visible while idle, as required.
The plain loop has no event loop to push into, so it drains a sequenced note log before each prompt.

**Dedup fix.** `notes` keeps its dedup (startup-note rendering and existing tests depend on it), but
every `_add_note` call also appends `(seq, message)` to a bounded event log and fires the listeners —
unconditionally — so a repeat outage is surfaced again.

Output: MCPManager API additions, stdio stderr capture + ExceptionGroup unwrapping, three surfaces
(TUI push, `/tools` state, plain loop), and tests at unit / integration / TUI level.
</objective>
