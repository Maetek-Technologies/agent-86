<objective>
Close the evidence gap for MCP-23 and research Open Question 4 (non-stdio transports): the reconnect
loop is proven against a real re-spawned stdio process, and the death signal is exercised against the
real SSE and streamable-HTTP fixtures (orchestrator default 4: include HTTP/SSE kill tests if
feasible, otherwise record accepted risk explicitly).

SDK reading done at planning time (verify, don't assume): for SSE, the `sse_reader` task owns the read
stream's writer, so a dropped SSE connection should close the read stream (passive detection). For
streamable HTTP, the read stream's writer is owned by `post_writer`, which lives until teardown — so a
killed HTTP server may only be detected when the NEXT request fails (its POST error crashing the
transport task group). The test therefore allows "detected passively OR on the next call", and
records which one each transport showed.

Output: two integration tests (+ an accepted-risk record if a transport cannot be detected).
</objective>
