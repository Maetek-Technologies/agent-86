Make a mid-session server death observable, and make it clear both dicts and name the server in the
error — MCP-26 (SC1 + SC2). This is the load-bearing plan: MCP-23's reconnect (plan 12-03) and the
registry sync (plan 12-04) both hang off the death signal and the `on_tools_changed` hook defined
here.

Purpose: today a killed stdio server leaves `_serve` parked forever on `close_event.wait()`, with
`_sessions` and `_server_tools` both still populated (12-RESEARCH.md "The empirical correction").

**Planner correction to the research (read this before implementing).** 12-RESEARCH.md recommends
using `message_handler`'s `Exception` branch as the death signal. Reading the installed SDK
(`.venv/Lib/site-packages/mcp/shared/jsonrpc_dispatcher.py:476-525`, `mcp/client/stdio.py:141-166`)
shows this does NOT fire on a real stdio kill: on subprocess EOF, `stdout_reader` just exits
`async with read_stream_writer:` which closes the stream; the dispatcher's `async for item in
self._read_stream` then ends normally, it calls `_fan_out_closed()` (which is where the observed
`MCPError: Connection closed` comes from) and returns — **no Exception item is ever delivered to
`message_handler`.** Conversely, Exception items that DO reach `message_handler` are mostly
non-fatal (`_parse_line` failure on one malformed stdio line, an SSE/HTTP parse error) and the
stream keeps going. Therefore:
- The death signal is **end-of-stream on the read stream**, observed by wrapping the transport's
  read stream in `_EOFWatchStream` before handing it to `ClientSession`. This sits above the
  transport, so it is transport-agnostic (stdio / SSE / streamable HTTP all feed ClientSession a
  read stream).
- `message_handler` IS installed (the seam the research identified, and the one MCP-24 will later
  extend for `list_changed`), but its `Exception` branch only records the latest transport error
  as the *cause text* for the disconnect note; its notification branch stays a no-op.
- A post-connect exception escaping the transport's own task group (the `except` path) is also
  treated as a drop.

Output: death detection + named errors in `mcp_client.py`, unit-tested with a fake transport whose
read stream can really be closed mid-session.

3. New class `_EOFWatchStream` (module level, near `_get_client_session`):
```python
class _EOFWatchStream:
    """Wrap a transport read stream; call ``on_eof`` once when the stream ends.

    The SDK never tells a ClientSession's owner that the transport died: on a killed stdio
    server the dispatcher's read loop simply reaches end-of-stream, fans ``Connection closed``
    out to pending requests, and returns — nothing reaches ``message_handler``. Watching the
    stream ClientSession reads from is the one transport-agnostic place that end is visible.
    """

    def __init__(self, inner: Any, on_eof: Callable[[], None]) -> None:
        import anyio  # lazy: only ever constructed inside _serve_once, where mcp is installed

        self._inner = inner
        self._on_eof = on_eof
        self._fired = False
        self._closed_errors = (anyio.EndOfStream, anyio.ClosedResourceError, anyio.BrokenResourceError)

    @property
    def last_context(self) -> Any:
        return getattr(self._inner, "last_context", None)

    def _fire(self) -> None:
        if not self._fired:
            self._fired = True
            self._on_eof()

    async def receive(self) -> Any:
        try:
            return await self._inner.receive()
        except self._closed_errors:
            self._fire()
            raise

    def __aiter__(self) -> _EOFWatchStream:
        return self

    async def __anext__(self) -> Any:
        try:
            return await self._inner.__anext__()
        except StopAsyncIteration:
            self._fire()
            raise
        except self._closed_errors:
            self._fire()
            raise

    def close(self) -> None:
        close = getattr(self._inner, "close", None)
        if close is not None:
            close()

    async def aclose(self) -> None:
        await self._inner.aclose()

    async def __aenter__(self) -> _EOFWatchStream:
        return self

    async def __aexit__(self, *exc_info: Any) -> None:
        await self._inner.aclose()
```
Our own `aclose()`/`__aexit__` deliberately do NOT fire: a deliberate teardown cancels the dispatcher rather than draining it to EOF.
