<objective>
Make the live GitHub connection the Phase 10 audit never made — BEFORE any implementation is
written (roadmap Phase 15 "Risk / constraint"). A human registers a classic GitHub OAuth App; the
executor then drives the installed `mcp` SDK's own `OAuthClientProvider` directly (a throwaway

browser, lists GitHub's real tools, and records every finding later plans depend on.

Predicted findings this spike must confirm or refute (from reading the installed SDK, mcp 2.0.0):
- **P1 — token endpoint format.** The SDK builds the token request with only
  `Content-Type: application/x-www-form-urlencoded` (no `Accept`), and parses the response with
  `OAuthToken.model_validate_json`. GitHub's `/login/oauth/access_token` returns
  form-encoded `access_token=...&scope=...` unless `Accept: application/json` is sent. Expected:
  run A (no Accept) fails at token parsing; run B (Accept added by a wrapper Auth) succeeds.
  DANGER: a run-A failure message may contain the real token — all spike output is redacted.
- **P2 — scope selection.** The SDK overwrites `client_metadata.scope` on the 401 (Step 3,
  `oauth2.py:691`) with PRM `scopes_supported` (all ten GitHub scopes) and appends
  `offline_access` (GitHub's AS metadata lists it). A configured scope is therefore only honoured
  by rewriting the `scope` query parameter of the authorization URL inside `redirect_handler`.
- **P3 — DCR skip.** A pre-seeded `TokenStorage.get_client_info()` with `issuer` left `None`
  skips registration (`oauth2.py:699`) and is never discarded by the SEP-2352 issuer check
  (`utils.py:352`: `if client_info.issuer is None: return True`).
- **P4 — iss.** GitHub's AS metadata sets `authorization_response_iss_parameter_supported: true`,
  so the callback must capture `iss` and pass it in `AuthorizationCodeResult`.

Pre-committed rulings (the executor applies these; it does not re-decide them):
- F1: plan 15-03's `AcceptJSONAuth` wrapper ships **unconditionally** (harmless when a server
  already answers JSON); the spike records why.
- F2: if run B succeeds with `http://127.0.0.1:8765/callback`, plans 15-02/15-03 use
  `oauth_redirect_port` default `8765`, `REDIRECT_HOST = "127.0.0.1"`, `REDIRECT_PATH = "/callback"`.
  If GitHub rejects it and the human re-registers `http://localhost:8765/callback`, the host
  becomes `localhost`. Record which.
- F3: `oauth_scopes` ships with default `None` (the MCP spec's own selection, which is what the
  SDK sends); narrowing is an opt-in documented in the README using run C's tool count.
- F4: every run must show **0** requests to a `/register` URL; any non-zero count sets the spike
  verdict to `blocked`.
- F5: if GitHub rejects the RFC 8707 `resource` parameter the SDK sends, the verdict is `blocked`.
- Verdict: `complete` if run B listed at least one tool; otherwise `blocked — <exact redacted
  error>`. On `blocked`, STOP: plans 15-02+ must not start; return a checkpoint to the user.

Output: `15-EVIDENCE.md` (spike half only; plan 15-06 appends the agent86 half).
