<objective>
Wire 15-03's module into the MCP client so `auth = "oauth"` actually does something (MCP-17
SC1/SC2 through agent86 itself), without changing a single byte of behaviour for existing
servers. Hook point is the one the audit and research named: `_streamable_http`
(`mcp_client.py:1694`) gains a keyword-only `auth`. SSE is deliberately NOT wired (research
Pitfall 5 — GitHub is streamable-HTTP only; 15-02's validator already rejects oauth on sse).

Design rulings (planner's discretion, recorded so the executor does not re-decide):
- `auth` reaches the transport through a new `_HTTP_AUTH` ContextVar set in `_serve_once`, exactly
  like `_STDIO_ERRLOG` — many tests replace `_open_transport` with a bare
  `(cfg, env_passthrough=None)` fake (comment at `mcp_client.py:1790-1794`), so its signature
  must not change (research Pitfall 4).
- One `InMemoryTokenStorage` per server name on the manager, created/updated in `start_server`,
  reused by every `_serve` reconnect attempt and kept across `stop_server` (a `/config mcp`
  restart does not re-prompt); cleared by `close()`. A fresh `build_oauth_auth(...)` provider is
  built per connection attempt (its SDK context caches discovery; storage carries the token).
- The secret lives only inside the storage's client record, never in the resolved cfg copy.
- `notify` is bound to `self._add_note` (thread-safe, non-blocking by contract).
</objective>
