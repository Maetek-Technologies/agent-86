Rulings applied (recorded for executor and verifier):
- Research Open Question 1 — the cap applies to `call_tool` (ADR 0004's named site,
  `_content_to_text`) AND to the text returned by `read_resource` and `get_prompt`, using the same
  per-server `max_result_chars` and the same marker. ADR 0004 names only `_content_to_text`, but
  the roadmap goal is capability-framed ("an oversized tool result truncates visibly"), a resource
  read or prompt render feeds the same context budget, and no reason against it was found. The
  list-style outputs (`list_resources`, `list_prompts`, `list_resource_templates`, `complete`) are
  NOT capped — they are bounded by list length and ADR 0004 does not reach them. 13-06 records this
  extension in ARCHITECTURE §7; ADR 0004 itself is not edited (accepted ADRs are records).
- Phase 11's `_resource_contents_to_text` / `_prompt_messages_to_text` marker text stays
  byte-for-byte (Pitfall 5 option (a)).
- `structured_content` stays unread (ADR 0004; `CAP-STRUCTURED-OUTPUT` stays out).
- `call_tool` keeps returning `str`; no new `ToolResult.metadata` key is added for MCP tool calls
  (the marker carries the facts; `run --json` stays additive-only by adding nothing).
- Discovered defect fixed here because this plan rewrites the function it lives in:
  `_content_to_text` reads `getattr(result, "isError", False)`, but mcp 2.0's `CallToolResult`
  field is `is_error` (verified at plan time: fields are `meta, content, structured_content,
  is_error, result_type`), so server error results have silently lost their `ERROR: ` prefix. Read
  `is_error` first, falling back to `isError` for older SDKs.

```python
def _content_to_text(
    result: Any, *, limit: int = DEFAULT_MCP_MAX_RESULT_CHARS, server: str = ""
) -> str:
    """A tools/call result as prompt text: every block rendered (MCP-25), capped (MCP-22).

    Non-text blocks go through ``render_content_block`` — a named marker, never ``str(chunk)``'s
    Python repr, never inlined base64. The joined body is cut at ``limit`` (the server's
    ``max_result_chars``, ADR 0004) with a visible marker; ``structured_content`` is not read
    (ADR 0004 scopes it out). Never raises.
    """
    parts = [render_content_block(chunk) for chunk in getattr(result, "content", None) or []]
    body = "\n".join(parts) if parts else "(no content)"
    body = truncate_result(body, limit, server)
    is_error = getattr(result, "is_error", None)
    if is_error is None:
        is_error = getattr(result, "isError", False)  # pre-2.0 SDK spelling
    return f"ERROR: {body}" if is_error else body
```
