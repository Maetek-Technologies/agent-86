<objective>
MCP-20 proper: schema deferral on `MCPTool`, per ADR 0003, plus the instructions capture that
feeds plan 14-02's system-message section.

Rulings (recorded for executor and verifier):
- **Unconditional, no config field** (research Open Question 2, orchestrator ruling 2). Every
  `MCPTool` whose server schema has at least one property is deferred; `_MCPCapabilityTool`
  synthetic tools are not. `config.py` is not touched. Task 1's provider-shape tests are the
  Pitfall 1 check that would overturn this; if any fails, stop and report (do not add a flag).
- **Stub = `ToolSpec`'s own default** `{"type": "object", "properties": {}}` (types.py). Every
  provider adapter already sends that shape for argument-less tools, so no adapter meets a new
  shape. A fresh dict per `spec()` call (never a shared module-level mutable).
- **Materialise on first execution, success or failure.** Research suggested "first successful
  call"; that would deadlock a tool whose first call fails *because* the model never saw the
  schema. The flag flips at the top of `run()` — i.e. only when the registry actually
  dispatched it (an `allowed-tools` refusal or unknown-tool path never reaches `run()`, matching
  research's anti-pattern note). The flip is synchronous, inside the step, before `run()`
  returns, so the next `_build_request` in the same turn reads the real schema from
  `registry.specs()` and `_context_budget` subtracts it (ADR 0003's "inside the step that
  triggers it"; research Pitfall 4: no new hook, `_context_budget` signature and its 2 call
  sites unchanged).
- **Visible, synchronous first-use cost.** If the first call omits any of the real schema's
  `required` keys, `run()` returns `ok=False` naming them and does not call the server (a
  side-effecting server never receives a guessed call). Every first-use `ToolResult` carries
  `metadata={"schema_materialized": True}` (tool-result metadata, not a `run --json` key —
  `run --json` stays untouched).
- **Reconnect** re-lists tools as fresh (deferred) `MCPTool` objects — accepted: history already
  shows the model the arguments it used, and the required-key precheck only fires if it omits
  them. `list_changed` (14-04) preserves object identity, and with it the flag.
- **Instructions**: `session.initialize()`'s result is no longer discarded;
  `InitializeResult.instructions` (stripped-empty → `None`) is stored per server in
  `self._instructions`, set atomically beside `self._sessions[name]` and popped beside it in
  `_serve_once`'s `finally` and in `stop_server`.
</objective>

```python
#: ADR 0003: until first use, an MCP tool advertises its NAME with this stub instead of the
#: server's schema. It is ToolSpec's own default-empty shape — what every provider adapter
#: already sends for argument-less tools — so no adapter meets a new wire shape (Pitfall 1).
_DEFERRED_NOTE = " [argument schema loads on first call]"


def _deferred_schema() -> dict[str, Any]:
    """A fresh stub each call: specs are handed to adapters that may decorate them."""
    return {"type": "object", "properties": {}}


def _missing_required(schema: dict, arguments: Any) -> list[str]:
    """The schema's ``required`` keys absent from ``arguments``. Never raises."""
    required = schema.get("required") if isinstance(schema, dict) else None
    if not isinstance(required, list):
        return []
    given = arguments if isinstance(arguments, dict) else {}
    return [k for k in required if isinstance(k, str) and k not in given]
```
